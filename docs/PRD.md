# PRD — 사내 링크 대시보드

## 1. 배경과 문제

사내 구성원이 자주 쓰는 시스템 주소를 기억하지 못해 슬랙에 반복해서 묻습니다.
개인 브라우저 북마크는 공유되지 않고, 노션 문서는 검색이 느리고 파비콘이 없어 훑어 읽기가 어렵습니다.

**해결할 문제**: "그거 주소 뭐였지?"를 없앤다.

## 2. 사용자와 맥락

- 주 사용자: 사내 구성원(비개발자 포함). 하루 3~10회 들어와 10초 안에 링크 하나 누르고 나갑니다.
- 관리자: 1~2명. 링크 등록·분류·정리를 담당합니다.
- 데이터 규모: 현재 290개 / 10개 상위 카테고리. 계속 늘어납니다.
- 환경: 데스크톱 1440px 주력, 모바일 375px 지원.

## 3. 성공 기준

1. 처음 온 사람이 3초 안에 "여기 뭐가 있는지" 구조를 파악한다.
2. 재방문자가 **클릭 2회 이내**(또는 검색어 입력 → Enter)로 목표 링크에 도달한다.
3. 링크 이름을 정확히 모르고 "대충 이런 거"만 아는 상태에서도 찾아낸다.
4. 링크가 늘어나도 1~3이 유지된다.
5. 마우스 없이 키보드만으로 검색 → 이동이 가능하다.

### 하드 제약
- 1440×900 첫 화면에 클릭 가능한 링크가 최소 30개 보인다. (홈: 즐겨찾기 n + 매일 12 + 운영 중 16)
- 히어로 배너·일러스트·그라데이션·장식 아이콘·마케팅 카피 금지.
- 라이트 모드, 무채색 + 파비콘. 카테고리를 색으로만 구분하지 않는다.
- 항목 표시 정보: 파비콘 + 이름 + 한 줄 설명 + 주소 + **눈 아이콘 + 누적 클릭 수**.
- **모든 화면이 같은 카드를 씁니다.** 홈·카테고리 목록·즐겨찾기 전부 동일한 사각 카드 그리드이며, 행 목록 형식은 관리자 화면에서만 씁니다.

## 4. 정보 구조

3계층입니다.

```
0단  내 즐겨찾기           (방문자 개인이 핀으로 담음, 개수 제한 없음)
1단  매일 사용하는 사이트   (관리자가 직접 고정, 최대 12개, 전사 공통)
2단  현재 운영 중인 사이트   (회사가 직접 운영하는 서비스 16개)
3단  분류별 전체 목록
```

**홈에는 0·1·2단만 둡니다.** 나머지는 좌측 사이드바로만 들어갑니다.

0단과 1단은 성격이 다릅니다. **1단(매일)은 관리자가 정해 모두에게 같은 것이 보이고**,
**0단(즐겨찾기)는 각 방문자가 직접 담아 그 사람에게만 보입니다.** 홈 카드에는 핀을 노출하지 않고(즐겨찾기 섹션 제외),
다른 모든 화면의 카드에서 핀을 눌러 담습니다.

## 6. 클릭 집계와 어뷰징 방어

수집: 링크를 열기 직전에 비동기로 `clicks`에 1건 insert. 페이지 이동을 막지 않습니다.

방어 규칙 (프로토타입에 1·2 구현됨)
1. **쿨다운**: 같은 방문자·같은 링크는 30초 안에 재클릭해도 세지 않습니다.
2. **일일 상한**: 같은 방문자·같은 링크 하루 10회까지만 집계합니다.
3. **방문자 익명 ID**: 로컬 스토리지 UUID + IP 해시를 함께 저장해 "총 클릭"과 "사람 수(unique)"를 분리 표시합니다.
4. **서버 rate limit**: Edge Function에서 IP당 분당 30회 초과 무시.
5. **일괄 열기 구분**: "한 번에 열기"는 `bulk` 플래그로 기록해 순위 왜곡을 막습니다.

통계 화면에서 **순위는 unique 기준, 절대값은 참고용**으로 안내합니다.

## 7. 데이터 모델 (Supabase / Postgres)

```sql
categories (
  id            uuid primary key default gen_random_uuid(),
  name          text not null unique,
  parent_id     uuid references categories(id) on delete set null,  -- 하위 카테고리
  sort_order    int  not null default 0,
  created_at    timestamptz default now()
);

bookmarks (
  id            uuid primary key default gen_random_uuid(),
  category_id   uuid references categories(id) on delete set null,  -- 상위 또는 하위 id
  title         text not null,
  url           text not null,
  description   text,
  tags          text[] default '{}',
  favicon_url   text,
  is_pinned     boolean not null default false,   -- 매일 사용하는 사이트 (최대 12)
  sort_order    int not null default 0,
  created_at    timestamptz default now(),
  updated_at    timestamptz default now()
);

-- 개인 즐겨찾기(P10): 방문자 계정이 없으므로 1단계에서는 DB 테이블을 두지 않고
-- 브라우저 localStorage에 bookmark_id 목록으로만 저장합니다. (프로토타입 동작과 동일)
-- 향후 사내 SSO를 붙이면 아래 테이블로 승격합니다.
-- favorites (user_id uuid, bookmark_id uuid, created_at timestamptz, primary key (user_id, bookmark_id));

clicks (
  id            bigserial primary key,
  bookmark_id   uuid references bookmarks(id) on delete cascade,
  visitor_hash  text,          -- 익명 방문자 식별 (UUID + IP 해시)
  is_bulk       boolean default false,
  clicked_at    timestamptz default now()
);
create index on clicks (bookmark_id, clicked_at desc);
create index on clicks (clicked_at desc);
```

### RLS
- `categories`, `bookmarks`: 익명 `select` 허용. `insert/update/delete`는 인증된 관리자만.
- `clicks`: 익명 `insert`만 허용, `select`는 관리자만.
- 고정 최대 12개는 트리거 또는 애플리케이션 레벨에서 강제합니다.

### 데이터 이관
`data/links.json`의 290건을 그대로 seed로 씁니다. 필드 매핑:

| JSON | DB |
|---|---|
| `title` | `bookmarks.title` |
| `url` | `bookmarks.url` (utm·gclid 등 추적 파라미터 제거 완료) |
| `desc` | `bookmarks.description` |
| `group` + `sub` | `categories` 2계층으로 생성 후 `category_id` |
| `tags` | `bookmarks.tags` |
| `pinned` | `bookmarks.is_pinned` |
| `order` | `bookmarks.sort_order` |
| `added` | `bookmarks.created_at` (unix seconds) |
| `data/icons/<id>.png` | `bookmarks.favicon_url` (스토리지 업로드 후 URL) |

## 8. AI 의미 검색

키워드 검색으로 못 찾는 문장형 질의("휴가 어떻게 쓰는지")를 처리합니다.

- 트리거: "AI 검색" 버튼 클릭 또는 ⌘↵ (매 타자마다 호출하지 않습니다)
- 입력: 질의문 + 전체 링크의 `title/description/tags/category` 요약
- 출력: 링크 3~5개 + **각각 왜 골랐는지 한 줄 근거**
- 결과는 키워드 결과와 시각적으로 분리하고 소요 시간을 표시합니다
- 구현: pgvector 임베딩 검색 또는 LLM 호출 중 선택. 프로토타입은 의도 사전(10종) + 토큰 겹침 폴백으로 흉내냅니다

## 9. 개발 단계

1. **1단계 — 공개 화면 읽기 전용**: 스키마 + seed + 홈 + 사이드바 + 카테고리 목록 + 파비콘. 클릭 집계 포함
2. **2단계 — 검색**: ⌘K 팔레트, 키보드 이동, 한 번에 열기
3. **3단계 — 관리자**: 로그인, 카테고리·링크 CRUD, 드래그 정렬, 고정 관리
4. **4단계 — 통계·정리**: 클릭 집계 대시보드, 어뷰징 방어, 정리 도구
5. **5단계 — AI 검색**: 임베딩 또는 LLM 연동

## 10. 이번 범위에서 제외

- 즐겨찾기의 기기 간 동기화 (계정이 없으므로 브라우저 단위 저장까지)
- 사용자 계정·권한(관리자 계정 1~2개만)

- 링크 유효성 자동 검사(죽은 링크 탐지)
